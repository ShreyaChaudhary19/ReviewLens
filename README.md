# ReviewLens — Fake Review Detector Web UI

A dark, responsive React + Vite frontend and FastAPI backend for the existing Fake Review Prediction project. The frontend includes overview analytics, single review inference, CSV batch inference/export, model metrics, dataset preview, and project notes.

## Important: preserve and connect your existing model

This package intentionally does **not** contain or replace your trained model, dataset, or model artifacts. Copy your existing `artifacts` and `data` folders from `Fake-Review-Prediction` into this folder. Then configure `backend/main.py` to use the exact artifact format you already trained.

The default loader expects:
- `artifacts/model.joblib` containing either a scikit-learn Pipeline (vectorizer + classifier) or a classifier, and
- optionally `artifacts/vectorizer.joblib` if the vectorizer is saved separately.
- `data/reviews.csv` with `review` and `label` columns.
- optionally `artifacts/metrics.json` with the metrics generated by your existing training script.

If your existing filenames differ, set PowerShell environment variables before starting the backend, for example:

```powershell
$env:MODEL_PATH = "C:\Users\Shreya\OneDrive\Projects\Fake-Review-Prediction\artifacts\YOUR_EXISTING_MODEL_FILE.joblib"
$env:VECTORIZER_PATH = "C:\Users\Shreya\OneDrive\Projects\Fake-Review-Prediction\artifacts\YOUR_EXISTING_VECTORIZER_FILE.joblib"
$env:DATASET_PATH = "C:\Users\Shreya\OneDrive\Projects\Fake-Review-Prediction\data\reviews.csv"
```

If the classifier was saved without a vectorizer or preprocessing pipeline, use the same preprocessing and vectorizer from your current `app.py`/`train_model.py`. Do not retrain or rename artifacts just to fit the scaffold. If `joblib.load()` raises an error (including the previous KeyError), use the exact Python environment and dependency versions used to save the model.

## Windows PowerShell setup

Open a new PowerShell window. Keep your existing project intact; create a separate copy for the new web interface.

1. Extract this ZIP to a folder such as `C:\Users\Shreya\OneDrive\Projects\ReviewLens-Web`.
2. Copy your existing `artifacts` and `data` folders into `ReviewLens-Web` (merge only by copying; don't delete or overwrite the original project).
3. Open PowerShell in the extracted folder:

```powershell
cd "C:\Users\Shreya\OneDrive\Projects\ReviewLens-Web"
```

4. Create and activate a backend virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
```

5. If your model artifact names are different, set `MODEL_PATH`, `VECTORIZER_PATH` and `DATASET_PATH` as shown above. Then start the API:

```powershell
python -m uvicorn backend.main:app --reload
```

The API runs at `http://127.0.0.1:8000`; health information is at `http://127.0.0.1:8000/api/health`.

6. Open a second PowerShell terminal and install the frontend packages (Node.js LTS must be installed):

```powershell
cd "C:\Users\Shreya\OneDrive\Projects\ReviewLens-Web\frontend"
npm install
npm run dev
```

7. Open the local URL Vite prints, usually `http://localhost:5173`.

## API endpoints

- `GET /api/health` — model loading status
- `GET /api/overview` — dataset counts and saved metrics
- `POST /api/predict` — JSON `{ "review": "..." }`
- `POST /api/batch` — multipart CSV upload
- `GET /api/dataset-sample` — small dataset preview

## Metrics and scientific integrity

The dashboard defaults to the previously reported test values if no metrics JSON is present: accuracy 88.125%, fake precision 83.8889%, fake recall 94.375%, fake F1 88.8235%, 320 test examples. Put your actual training output in `artifacts/metrics.json` to source the metrics from the saved run. Never describe these as new measurements unless the evaluation was rerun.

Predictions are model estimates, not proof that a reviewer is deceptive. The interface deliberately avoids claiming explainable AI feature importance unless you add a validated explanation method.
